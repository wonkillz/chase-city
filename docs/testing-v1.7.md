# CHASE CITY V1.7 재현 및 검증

2026-11-13. V1.6 main `5e15b10` 기반. 체포·추격 충돌·화면 밖 증원만 수정했다. 이전 검증은 [V1.6 기록](testing-v1.6.md)에 보존한다.

## 원인과 수정

- 기존 체포 공간 검사는 제자리에서 반복 회전하는 가상 자세를 허용했다. 실제 차의 전진/가속/조향으로는 지날 수 없는 길도 출구로 판단할 수 있었다. 이번 검사는 실제 입력 세 가지(중립/좌/우), 조향 응답, 가속, 차체 전체와 중간 자세를 1.8초 동안 탐색한다. 이미 닿아 있는 접촉의 미끄러짐 여유는 0.12이며 새 관통은 허용하지 않는다. 접촉 안쪽 속도는 실제 충돌 해석처럼 제거하고 검사하므로 밀림 한 프레임이 열린 길을 막힌 길로 오인하지 않는다.
- 포위 판정이 한 프레임 열리면 게이지가 계속 손실되는 문제에는 0.35초 동결을 적용했다. 열린 상태에서는 동결 중에도 게이지가 증가하지 않는다. 이후 초당 5초분 감소한다. 체포 직전에는 공간을 다시 검사하며 열린 출구에서 99%가 100%로 넘어가지 않는 검사를 추가했다.
- 기존 저속 포위 진입 범위가 넓어 정상 추격도 조기 감속했다. 이제 실제 막힘/낮은 순이동과 3대 이상 근접 여부로 포위 후보를 정한다. 추격은 예측 경로와 서로 다른 측방 차단 경로를 사용하고, 경찰 간 회피는 저속 포위에서만 적용한다. 실제 차체 SAT 접촉의 법선/상대 속도로 피해를 계산한다. 상대 속도 10 미만 또는 법선 접근 5 미만인 접촉은 피해가 없으며 저속 포위 보호도 유지한다. 강한 충격 피해는 최대 60, 쿨다운 0.8초다. 폭발은 내구도 0 또는 실제 연쇄 피해에서만 발생한다.
- 기존 spawn은 거리 27–48만 검사하고 전방을 우선했다. 이제 현재 렌더 카메라를 물리/AI와 공유해 실제 프러스텀을 검사한다. 차체 전체와 8 단위 여유, 거리 45–115, 후방 내적 ≤ -12, 실제 기본 도로 노드, 장애물과 A* 연결을 모두 만족해야 한다. 건물에 가려진 화면 안 지점은 생성 후보가 아니다. 후보가 없으면 0.3초 후 재시도하며 순간이동 fallback은 없다. 최초 4대만 예외이며 이후 증원과 2.5초 재투입은 같은 함수를 쓴다.

## 60초 자연 주행 측정

[원시 기록](pursuit-v1.7.json), 재현: `node scripts/measure-v17.js`.

정상 START 위치, 기본 내구도/속도/경찰 수/바리케이드를 유지했다. 입력은 좌우 조향뿐이며 경찰 배치·폭발·내구도를 수정하지 않는다. PC 1100×740, 휴대폰 390×664의 실제 ChaseCamera, 일반/급회전 각각 시드 1–6, 직진 시드 1–2로 총 28회다. 고정 60 Hz에서 **플레이한 시간 60초**를 측정했으며 조기 실패는 정상 RESTART 후 계속해 60초를 채웠다. 따라서 모든 기록이 한 실행에서 60초 생존한 것은 아니다. 재시작 횟수와 실행별 이벤트를 원시 기록에 함께 남겼다.

| 카메라 | 입력 | 회수 | 자연 폭발 평균 | 화면 내 평균 | 경찰 노출 시간 | 재시작 합계 |
|---|---|---:|---:|---:|---:|---:|
| PC | 일반 | 6 | 13.17 | 10.83 | 92.22% | 3 |
| PC | 급회전 | 6 | 11.50 | 11.00 | 90.78% | 3 |
| 휴대폰 | 일반 | 6 | 14.17 | 11.33 | 90.89% | 1 |
| 휴대폰 | 급회전 | 6 | 11.33 | 10.17 | 93.44% | 2 |
| PC | 직진 유지 | 2 | 6.00 | 6.00 | 96.67% | 4 |
| 휴대폰 | 직진 유지 | 2 | 6.00 | 6.00 | 100% | 4 |

일반/급회전 24회 화면 내 평균 **10.83회**, 전체 28회 평균 **10.14회**다. **재시작 없이 연속 60초를 마친 16회만 보면 평균 12.50회**(PC 7회 평균 14.00 / 휴대폰 9회 평균 11.33)다. 목표 8–15는 평균 기준 초기 밸런스로 충족했으나 **개별 실행 0–18회로 보장되지 않는다**. 직진 경로는 6회로 목표 미만이며 조기 실패도 잦다. 이를 맞추기 위한 강제 사고/폭발은 추가하지 않았다.

폭발은 경찰차 1대당 1회이며, 같은 순간 연쇄 폭발한 차량도 각각 집계한다.

28회 실제 경찰 간 피해 접촉 681회, 폭발 325회(차량 접촉 136 / 연쇄 188 / 벽 접촉 1)다. 벽 원인 1회는 PC 급회전 시드 4의 58.83초, 속도 11.03에서 기록됐다. 벽 피해 자체는 유지하되 반복 돌진을 피하는 경로/안전 검사를 유지했다. 증원 107 + 재투입 281 = **388회**, 화면 안 생성 **0**, 전방 생성 **0**, 생성 거리 45.18–114.36. 각 생성의 위치·각도·거리·후방 내적·카메라 행렬·확장 차체 투영값을 원시 파일에 남겼다. 이 가시성 수치는 카메라 투영과 건물 레이 검사 기준이며 실제 브라우저 측정은 아래에 별도로 기록한다.

## 정상 시작 체포와 브라우저 검사

`tests/browser/v16.spec.js`의 정상 체포 검사와 `tests/browser/v17.spec.js`의 자연 추격 검사는 실제 requestAnimationFrame 게임 루프를 사용한다. 경찰 위치/내구도/게이지/시각을 덮어쓰거나 `Simulation.update`를 직접 호출하지 않는다. PC는 처음 5초 직진 후 우회전, 모바일은 START부터 우회전해 AI가 스스로 포위하도록 한다. 추가 정상 조향 경로 PC 즉시 우회전, 모바일 3초 이후 우회전도 Node 검사에 포함한다. 체포 마지막 구간의 폭발 수가 증가하지 않아야 하며 이전 고속 추격 사고와 구분한다.

자연 추격은 양쪽 화면에서 `stageDriver(2, 'evasive')`의 조향 입력만 사용한다. 실제 생성 첫 렌더 프레임에 차체 전체/여유가 화면 밖인지 다시 검사하고, 이후 도로를 주행해 화면 안에 들어온 시간과 좌표를 기록한다. 자연 충돌 피해와 실제 화면 안 폭발을 기록한다. 생성/진입/폭발/60초 장면에서 일반 일시정지 버튼으로 멈춰 캡처한다.

실행 중 소프트웨어 GPU 부하를 줄이기 위해 테스트에서만 내부 해상도 0.5와 정적 그림자 동결을 사용한다. 스크린샷은 1x 캔버스로 실제 렌더링한다. 게임 시간 배속이나 강제 진행은 없다. 모바일 WebKit 에뮬레이션이며 실제 iPhone 하드웨어의 FPS/발열은 측정하지 않았다.

잔해 30/60초·화면 밖 복귀·캐시 확장 검사는 별도 **강제 충돌 fixture**다. 정상 AI 주행의 자연 폭발 횟수에는 포함하지 않는다. 영구 잔해/화재·바리케이드·탈출·보상·투명화·사운드·조향은 기존 회귀 검사를 함께 실행한다.

## 최종 실행 결과

- 복구한 미커밋 V1.7 변경을 초기화하지 않았다. 별도 소스 백업을 만들었고 `src/` 23개 파일이 복구 이후 동일함을 비교했다. V1.6으로 되돌리거나 게임 콘텐츠를 추가하지 않았다.
- `npm test`: **75개 통과, 실패 0**. 도로 점유 검사에도 실제 카메라를 전달하도록 테스트를 보완한 뒤 해당 내비게이션 5개 검사를 추가 통과했다.
- **PC Chromium 16개 + iPhone 화면비 WebKit 16개 = 32개 고유 시나리오 최종 통과.** 모바일 핵심 3개/회귀 13개, PC 전체 16개, 카메라 경로 재검사 양쪽 2개로 총 34회 실행했다.
- PC의 기존 렌더링 fixture 경로(일반 주행 시드 2)는 **35.65초에 실제 BUSTED**가 발생해 41초 렌더링 검사에 최초 실패했다. 체포/내구도나 기존 assertion을 약화하지 않았다. 이 렌더링 fixture만 일반 주행 시드 3으로 바꿔 양쪽 엔진에서 재검사했다. 정상 AI 체포와 자연 추격 검사는 별도로 유지했다. 최초 실패를 포함한 실행별 결과도 원시 검증 파일에 보존했다.
- `npm run build`: 성공. Three.js 분리 청크 478.06 kB, 게임 청크 63.44 kB, CSS 8.82 kB. Cloudflare Pages 출력은 기존 `dist`다.
- 실제 프로덕션 preview(4173)에서 두 엔진 모두 START/타이머, 음소거, 일시정지/재개와 개발 진단 훅 제외를 확인했다. `/?debug`를 붙여도 프로덕션에는 `window.__CHASE__`가 없다.
